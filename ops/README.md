# FutureRobotic AI deployment operations — Build 02

The current Site is an owner-private preview. The portable account application and AWS templates are source deliverables, not an AWS deployment. Build 02 implements product services, browser wiring and offline checks. Start with `portable/docs/release/BUILD02_REPORT.md` and the stable-ID tracker for current evidence.

## Reproducible verification

Use Node 22.13+ and pnpm 11.25.0. `pnpm install --frozen-lockfile`; `pnpm exec tsc --noEmit`; `pnpm api:build`; `pnpm api:test`; `pnpm test:ui`; `pnpm runner:test`; `pnpm web:build`; `pnpm infra:build`; `INFRA_SYNTH_ONLY=true pnpm infra:synth`; `pnpm infra:test`.

The ordinary database suite uses PostgreSQL WASM when TEST_DATABASE_URL is unset. It validates SQL, migrations and service behavior but does not prove multiple native connections, failover or RDS performance. `pnpm api:test:native` creates a disposable PostgreSQL 16 Docker container and runs the full service suite. Never use a production database for TEST_DATABASE_URL. The container gate exits 2 when Docker is absent. Isolation probes require a separate approved runner host; see `runner/README.md`.

`docker compose -f portable/compose.yml up --build --wait` supplies PostgreSQL, migration, API/worker and standalone web at http://localhost:8080. Inject a random LOCAL_DB_PASSWORD into the process environment first. No development identity bypass exists. Real login still needs OAuth or OTP/human-verification configuration. No provider or payment key is included in compose. Docker/compose execution is blocked B01 in the authoring environment.

## AWS sequence

1. Owner selects account/role, domain/zone, two environments, launch countries, provider/merchant/email configuration, protected repository and support responsibility. This is B02–B09. Keep all secrets in protected service configuration, never chat or the repository.
2. Copy `release.config.example.json` outside the repository and fill actual account, domain, image digests, alert recipient and approved options. Never apply the offline `example.invalid` fixture. `INFRA_SYNTH_ONLY=true` only writes local CloudFormation; it does not contact or deploy AWS. The six offline stacks include the optional runner fleet.
3. Review the application and edge change sets. Use an owner-controlled CDK deployment role for initial infrastructure (not the narrower GitHub ECS role). The application imports `futurerobotic/ENV/application` and `/provider` Secrets Manager documents. All named ECS secret fields must exist even when an optional integration is disabled; use empty strings for deliberately disabled optional fields. Encryption/hash keys must be valid protected random values. API task receives identity/merchant secrets, worker receives the provider secret, browser task receives neither. Configure the TURNSTILE public site key and secret for hostname/action `login`.
4. Bootstrapping needs a first image before an ECS service can become healthy. Build/push source images using `build-images.mjs` in protected CI, or create the retained ECR repositories through an owner-approved bootstrap change set, then synthesize the final digest references. The current all-in-one stack has no automatic first-deploy bootstrap orchestration; this remains a staging gate. Do not force a healthy result while migration or image prerequisites are missing.
5. Create the RDS schema with the migration owner credential, run `runtime-bootstrap.mjs` with the protected generated runtime password, and smoke-test the restricted role. Use a private one-off migration task with the same image/CA and reviewed network access. Master/migration credentials never enter a serving task. New tables require an explicit grant review after each migration; runtime cannot alter migrations, operator enrollment or existing audit/ledger rows.
6. Validate staging before production: secure cookies and CSRF, each real login, OTP delivery/bounces, real AI output/cost/failure, file checksum/ownership, raw signed merchant events and refund, SSE through CloudFront, cache isolation, WAF rejection and private origin. Direct ALB has no public path; tighten the ALB ingress to the CloudFront VPC-origin managed security group after origin creation. Current code trusts exactly two proxy hops only on that private edge path; bypassing it invalidates client-IP rate-limit assumptions.
7. Execute load, native contention, failover, restore and incident drills. Record source SHA, exact image digests, environment, operator, timestamps and links to real logs in `release-gates.example.json` (copied to protected configuration). `check-release.mjs` fails closed until every required measured gate and owner decision is present. A boolean in the template is not evidence that a drill ran.
8. Configure GitHub protected staging/production environments, main-branch restrictions and approvals. OIDC subject is the exact repository + environment; the workflow also rejects non-main branches. Verify the actual trust failure from an untrusted branch. The role is scoped to product ECR/ECS and exact task roles. Run verification first, build images with provenance/SBOM, review ECR findings, then roll out approved digests. `deploy-service.mjs` requests old task definitions on failed stability/smoke checks; an operator must confirm rollback health.
9. Release to a small approved audience first, observe errors/latency/spend and payment/allowance reconciliation, then expand country availability. Worldwide marketing is blocked until the actual service/country matrix, support, privacy, fair-use and financial policies are approved and tested. No payment currency other than the proposed USD catalog is implemented.

## Protected server settings

Database: DB_HOSTNAME, DB_DATABASE, DB_USERNAME, DB_PASSWORD, DB_POOL_MAX; production PG_CA_FILE points to the bundled public RDS CA. Identity: APP_ORIGIN, APP_ENCRYPTION_KEY (32 random bytes, base64), AUTH_HASH_SECRET (at least 32 random characters), GOOGLE_CLIENT_ID/SECRET, GITHUB_CLIENT_ID/SECRET, SES_FROM_EMAIL, TURNSTILE_SECRET/SITE_KEY. Production startup requires RELEASE_CONFIGURATION_APPROVED=true and at least one configured public identity route. Configure OAuth callbacks at `https://DOMAIN/auth/google/callback` and `/auth/github/callback`.

Storage: S3_BUCKET, S3_KMS_KEY_ARN and AWS task role. Quarantined text files are bounded to 100 KB; valid content moves to a separate object prefix before temporary cleanup. Binary document parsers and malware scanning are not implemented. ZIP import handles bounded source text and rejects unsafe paths, links, duplicate names and expansion abuse.

AI: AI_HTTP_ENDPOINT (fixed HTTPS chat-completions-compatible endpoint), AI_HTTP_API_KEY, AI_MODELS_JSON (public registry IDs to approved provider model IDs), AI_INPUT_MICRO_USD_PER_MILLION and AI_OUTPUT_MICRO_USD_PER_MILLION (nonnegative integer micro-USD per million units), AI_RETENTION_APPROVED=true. AI_ENABLED controls browser availability. This adapter is provider-neutral and unverified against a live provider. Budget accounting conservatively charges the reserved maximum; actual provider invoice reconciliation remains required. Set provider_enabled and a nonzero daily budget through MFA operations only after readiness checks. A zero price must only represent an explicitly approved genuinely free route. No browser accepts the provider key.

Billing: PADDLE_MODE, PADDLE_API_KEY, PADDLE_WEBHOOK_SECRET, PADDLE_PRICE_IDS_JSON (`pro:month`, `pro:year`, `premium:month`, `premium:year`), APPROVED_COUNTRIES and BILLING_RELEASE_APPROVED. Webhook URL is `/webhooks/paddle`. Price metadata is checked against the shared cents catalog before checkout; only confirmed bound signed payment grants a new period. Annual monthly allowance scheduling, proration/refund policy and provider-side verified-country checks remain incomplete; keep paid launch closed until they are resolved. A self-reported country is not sufficient regulatory or tax enforcement.

Runner: RUNNER_ENDPOINT, worker-only RUNNER_SIGNING_KEY, trusted fleet public key. Runner_enabled defaults false. The optional fleet starts at zero and has no app/DB/provider IAM permissions. A baked, scanned AMI with runsc, cached pinned execution image and gateway systemd service is an owner/CI artifact. Current native probes have not run. Do not expose the runner gateway publicly or treat container argument tests as isolation proof.

## Operational procedures

See `RECOVERY.md`, `INCIDENTS.md`, `ACCEPTANCE.md` and `POLICY_DECISIONS.json`. `check-finance.sql` is a read-only exception detector, not an automatic money/credit repair tool. `http-probe.mjs` is a public, read-only availability probe. `load-probe.mjs` tests readiness saturation only and cannot establish AI/runner throughput. Run country probes from owner-selected regional CI agents with PROBE_REGION recorded. Proposed targets require owner approval and measurement.
